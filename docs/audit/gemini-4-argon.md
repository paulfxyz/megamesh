## What is good

- **Deep operational honesty and real-world trap coverage:** The five operational traps (inactive `/swapfile` causing `dnf` OOM on 1 GB RAM, Hostkey’s `"iptables": false` in `daemon.json`, legacy `iptables` kernel modules for `wg-easy` on EL9, `fail2ban` running with zero jails, and Docker’s `docker-forwarding` firewalld policy bypassing zone rules for published ports) are genuine time-savers that almost every tutorial misses.
- **Clean firewalld + Docker architecture:** Instead of fighting Docker’s `iptables`/`nftables` chains with brittle raw rules, keeping `wg-easy`’s UI port (`51821`) unpublished on an internal Docker bridge and publishing only `443/tcp` (Caddy) and `51820/udp` (WireGuard) works *with* Docker’s `docker-forwarding` policy rather than against it.
- **TLS-ALPN-01 only (no port 80):** Eliminating `tcp/80` entirely while keeping automatic Let's Encrypt issuance/renewal via Caddy on `tcp/443` keeps the external surface minimal.
- **No leaked secrets:** `.gitignore` is sensible, `scripts/status.sh:11` explicitly strips `private key` from `wg show` output, and `PROMPT.md:32` instructs the AI agent never to echo keys or passwords into its transcript.
- **Idempotency care:** Catching `firewall-cmd --set-log-denied=off` exit code 2 (`already_enabled`/`already_set`) and commenting out `50-redhat.conf` / `50-cloud-init.conf` shows the script was actually re-run against a live system.

## Verdict

**Grade: A- | Publishable as-is: No** (fix the two missing/broken items below in 5 minutes, then **Yes**).  
The v1.1.0 remediation of the three-model audit is exceptionally thorough: the SSH lockout guard, firewall ordering, Docker userland-proxy hairpin routing, `NET_ADMIN`-only capability reduction, and unattended `INIT_*` setup are all architecturally sound and cleanly implemented. However, a few bash `set -euo pipefail` traps were introduced in the new code, `egress.json` is missing from the repository bundle despite being linked in `README.md`, and re-running `install.sh` clobbers active VPN-only lockdown configurations.

## Nits

- **`config/Caddyfile` vs `docs/LOGBOOK.md:56` & `docs/HARDENING.md:106`:** The docs state the reference server has `vpn-only: ENABLED` since 2026-10-18, and `README.md:122` claims `config/` contains *"the exact files running on the reference server"*, but `config/Caddyfile` is still the open (non-lockdown) config.
- **`docs/LOGBOOK.md:42` vs `docs/LOGBOOK.md:69`:** Line 42 says `proxy-lockdown` is *"not enabled — the owner will say when"*, while line 56 and line 69 say it *was* enabled. That's chronological (step 20 vs step 22), which is fine, but placing the `## End state` block (lines 44–57) *before* steps 21–22 (lines 68–69) reads out of order. Move steps 21–22 above `## End state`.
- **`docs/TROUBLESHOOTING.md:15`:** Heading says `ss -tulpn shows no docker-proxy` as a symptom of `"iptables": false`, which was true in v1.0.0, but in v1.1.0 `"userland-proxy": false` is the default, so `docker-proxy` is *never* present even when working properly (`dockerd` binds the port directly or uses `iptables` DNAT). Update the heading to avoid confusing users.
- **`CHANGELOG.md:3`, `CHANGELOG.md:29`, `README.md:107`:** Release dates are all `2026-10-18` (acknowledged in `AUDIT.md:35` as intentional).

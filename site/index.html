Your own WireGuard VPN, one IP and root away

01 You run servers

The script

One idempotent bash file, every setting an environment variable, nothing interactive. Read it, then run it as root on a fresh VPS. Re-running is safe; it keeps your choices.

curl -fsSLO https://megamesh.sh/megamesh.sh
less megamesh.sh          # read it first
MEGAMESH_DOMAIN=vpn.example.com \
MEGAMESH_EMAIL=you@example.com \
bash megamesh.sh

02 You have an AI agent

The prompt

Paste one prompt into any agent that can run shell commands over SSH — Perplexity Computer, Claude Code, Codex, your own. It carries the goal, the safety rules, and every trap we hit so the agent starts where we finished.

The rules matter: your own key goes in first, passwords are never disabled before a key login has succeeded, secrets are never printed, and the agent asks before touching SSH or the firewall.

03 You just want a VPN

The deployer

Rent a VPS (any 1 GB box with CentOS Stream 9 will do), buy or reuse a domain, then give the deployer the IP, the root password, the domain and your email. It installs everything, waits, and hands over: point your domain at the IP, open it, log in with the admin account it created, scan a QR code.

Your root password transits through megamesh.sh for the minutes the install runs and is never stored. If that is not acceptable, use door 01 or 02 — same result.

What you get

Three doors.
Everything else is a black hole.

The public internet reaches exactly three ports. The firewall's default action is DROP, not reject: scanners get silence. Inside, two containers and a handful of host settings — all of them written down, none of them clever.

tcp/22 sshKey-only once a key exists, no forwarding, 3 tries. fail2ban bans for 24 h, doubling to 30 days.
udp/51820 wgWireGuard. Silent to anything that is not a valid handshake — to a port scanner it does not exist.
tcp/443 httpsCaddy with a Let's Encrypt certificate, serving the wg-easy admin. Optionally VPN-only: outsiders get redirected to a URL of your choice.
everything elseDropped. No port 80, no admin port, no Docker ports leaking through — only two are ever published.
icmpPing and the path-MTU types only, so the tunnel never stalls on big packets.

Inside the box

  • wg-easy v15 — peers, QR codes, stats, 2FA on the admin. Runs with NET_ADMIN only.
  • Caddy 2 — automatic TLS over 443 (no port 80), HSTS, strict headers.
  • firewalld — the three-door policy, bound to the interface that carries your default route.
  • fail2ban — the reference server had 76,073 failed SSH logins in 25 days before we touched it.
  • topgrade — weekly, pinned and checksum-verified: packages and container images, then a health check; a bad image is rolled back before you notice.
  • Swap guard, sysctl hardening, log rotation — the boring parts that keep a 1 GB box alive.
  • Unattended admin account — created before port 443 is reachable, so nobody can race you to the setup wizard.
Honest notes

What this is not.

Not a privacy service

Your VPS provider sees your traffic leave their network. Megamesh hides you from the café Wi-Fi and your ISP, not from a subpoena.

Not multi-tenant

One admin, your devices. wg-easy supports many peers, but the hardening assumes a single trusted operator.

Not finished by the deployer

Door 03 leaves SSH on a password until someone installs a key, and leaves 2FA and VPN-only mode for you to switch on. Have a techie friend spend twenty minutes with the hardening notes; it is already a good box before that.

Not tested everywhere

CentOS Stream 9 on a 1 vCPU / 1 GB VPS is verified end to end. Rocky, Alma, Debian and Ubuntu take their own code paths and have not been run. The repository says exactly what has and has not been exercised.
